# Сайт доставки еды Star Burger

Это сайт сети ресторанов Star Burger. Здесь можно заказать превосходные бургеры с доставкой на дом.

![скриншот сайта](https://dvmn.org/filer/canonical/1594651635/686/)


Сеть Star Burger объединяет несколько ресторанов, действующих под единой франшизой. У всех ресторанов одинаковое меню и одинаковые цены. Просто выберите блюдо из меню на сайте и укажите место доставки. Мы сами найдём ближайший к вам ресторан, всё приготовим и привезём.

На сайте есть три независимых интерфейса. Первый — это публичная часть, где можно выбрать блюда из меню, и быстро оформить заказ без регистрации и SMS.

Второй интерфейс предназначен для менеджера. Здесь происходит обработка заказов. Менеджер видит поступившие новые заказы и первым делом созванивается с клиентом, чтобы подтвердить заказ. Сайт сам подбирает рестораны, которым по силам весь заказ, и сортирует их по расстоянию до клиента — менеджеру остаётся передать заказ в ближайший. Там всё приготовят и сами доставят еду клиенту.

Третий интерфейс — это админка. Преимущественно им пользуются программисты при разработке сайта. Также сюда заходит менеджер, чтобы обновить меню ресторанов Star Burger.

## Что внутри

- Python 3.10+ и Django 5.2, база — SQLite (или любая, какую задать в `DATABASE_URL`)
- Django REST Framework для API, из которого заказывает фронтенд
- React + Parcel во фронтенде, собирается в бандлы `bundles/index.js` и `bundles/index.css`
- Геокодер Яндекса, чтобы считать расстояние от ресторана до клиента

## Как запустить dev-версию сайта

Для запуска сайта нужно запустить **одновременно** бэкенд и фронтенд, в двух терминалах.

### Как собрать бэкенд

Скачайте код:
```sh
git clone https://github.com/eshkere1/star-burger.git
```

Перейдите в каталог проекта:
```sh
cd star-burger
```

[Установите Python](https://www.python.org/), если этого ещё не сделали.

Проверьте, что `python` установлен и корректно настроен. Запустите его в командной строке:
```sh
python --version
```
**Важно!** Версия Python должна быть не ниже 3.10.

Возможно, вместо команды `python` здесь и в остальных инструкциях этого README придётся использовать `python3`. Зависит это от операционной системы и от того, установлен ли у вас Python старой второй версии.

В каталоге проекта создайте виртуальное окружение:
```sh
python -m venv venv
```
Активируйте его. На разных операционных системах это делается разными командами:

- Windows: `.\venv\Scripts\activate`
- MacOS/Linux: `source venv/bin/activate`


Установите зависимости в виртуальное окружение:
```sh
pip install -r requirements.txt
```

Создайте файл `.env` рядом с `manage.py` — проще всего скопировать заготовку и заполнить её:

```sh
cp .env.example .env
```

На Windows:

```sh
copy .env.example .env
```

Как минимум задайте в нём `SECRET_KEY`, остальные переменные разобраны в разделе
[Переменные окружения](#переменные-окружения). Случайный ключ можно сгенерировать так:

```sh
python -c "from django.core.management.utils import get_random_secret_key as k; print(k())"
```

Создайте файл базы данных SQLite и отмигрируйте её следующей командой:

```sh
python manage.py migrate
```

Чтобы было что смотреть, загрузите демо-магазин: три ресторана с настоящими московскими адресами, меню и десяток заказов, включая краевые случаи — заказ, который некому приготовить, и адрес, который не знает геокодер.

```sh
python manage.py loaddata demo_data
```

Создайте себе доступ в кабинет менеджера и в админку:

```sh
python manage.py createsuperuser
```

Запустите сервер:

```sh
python manage.py runserver
```

Откройте сайт в браузере по адресу [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Если вы увидели пустую белую страницу, то не пугайтесь, выдохните. Просто фронтенд пока ещё не собран. Переходите к следующему разделу README.

Кабинет менеджера живёт по адресу [http://127.0.0.1:8000/manager/](http://127.0.0.1:8000/manager/), админка — по адресу [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/). И туда, и туда пускают по логину суперпользователя, которого вы создали выше.

### Собрать фронтенд

**Откройте новый терминал**. Для работы сайта в dev-режиме необходима одновременная работа сразу двух программ `runserver` и `parcel`. Каждая требует себе отдельного терминала. Чтобы не выключать `runserver` откройте для фронтенда новый терминал и все нижеследующие инструкции выполняйте там.

[Установите Node.js](https://nodejs.org/en/), если у вас его ещё нет.

Проверьте, что Node.js и его пакетный менеджер корректно установлены. Если всё исправно, то терминал выведет их версии:

```sh
nodejs --version
# v16.16.0
# Если ошибка, попробуйте node:
node --version
# v16.16.0

npm --version
# 8.11.0
```

Версия `nodejs` должна быть не младше `10.0` и не старше `16.16`. Лучше ставьте `16.16.0`, её мы тестировали. Версия `npm` не важна. Как обновить Node.js читайте в статье: [How to Update Node.js](https://phoenixnap.com/kb/update-node-js-version).

Перейдите в каталог проекта и установите пакеты Node.js:

```sh
cd star-burger
npm ci
```

Команда `npm ci` создаст каталог `node_modules` и установит туда пакеты Node.js. Получится аналог виртуального окружения как для Python, но для Node.js.

Помимо прочего будет установлен [Parcel](https://parceljs.org/) — это упаковщик веб-приложений, похожий на [Webpack](https://webpack.js.org/). В отличии от Webpack он прост в использовании и совсем не требует настроек.

Теперь запустите сборку фронтенда и не выключайте. Parcel будет работать в фоне и следить за изменениями в JS-коде:

```sh
npm start
```

Дождитесь завершения первичной сборки. Это вполне может занять 10 и более секунд. О готовности вы узнаете по сообщению в консоли:

```
✨  Built in 10.89s
```

Parcel будет следить за файлами в каталоге `bundles-src`. Сначала он прочитает содержимое `index.js` и узнает какие другие файлы он импортирует. Затем Parcel перейдёт в каждый из этих подключенных файлов и узнает что импортируют они. И так далее, пока не закончатся файлы. В итоге Parcel получит полный список зависимостей. Дальше он соберёт все эти сотни мелких файлов в большие бандлы `bundles/index.js` и `bundles/index.css`. Они полностью самодостаточны, и потому пригодны для запуска в браузере. Именно эти бандлы сервер отправит клиенту.

Теперь если зайти на страницу  [http://127.0.0.1:8000/](http://127.0.0.1:8000/), то вместо пустой страницы вы увидите:

![](https://dvmn.org/filer/canonical/1594651900/687/)

Каталог `bundles` в репозитории особенный — туда Parcel складывает результаты своей работы. Эта директория предназначена исключительно для результатов сборки фронтенда и потому исключёна из репозитория с помощью `.gitignore`.

**Сбросьте кэш браузера <kbd>Ctrl-F5</kbd>.** Браузер при любой возможности старается кэшировать файлы статики: CSS, картинки и js-код. Порой это приводит к странному поведению сайта, когда код уже давно изменился, но браузер этого не замечает и продолжает использовать старую закэшированную версию. В норме Parcel решает эту проблему самостоятельно. Он следит за пересборкой фронтенда и предупреждает JS-код в браузере о необходимости подтянуть свежий код. Но если вдруг что-то у вас идёт не так, то начните ремонт со сброса браузерного кэша, жмите <kbd>Ctrl-F5</kbd>.

## Переменные окружения

Настройки проект читает из файла `.env`, который лежит рядом с `manage.py`. В репозиторий этот файл не попадает — там есть только заготовка `.env.example`, её нужно скопировать в `.env` и заполнить.

| Переменная | Обязательна | Значение по умолчанию | Зачем |
| --- | --- | --- | --- |
| `SECRET_KEY` | да | — | Секретный ключ Django. Им, например, зашифрованы пароли пользователей сайта. |
| `DEBUG` | нет | `True` | Отладочный режим: подробные страницы ошибок и раздача статики самим Django. На боевом сервере — `False`. |
| `ALLOWED_HOSTS` | нет | `127.0.0.1,localhost` | Домены, с которых разрешено открывать сайт, через запятую. [Документация Django](https://docs.djangoproject.com/en/5.2/ref/settings/#allowed-hosts). |
| `YANDEX_GEOCODER_API_KEY` | нет | пусто | Ключ API Яндекс.Геокодера. Без него сайт работает, но в кабинете менеджера вместо расстояний будет предупреждение, что координаты не определились. |
| `DATABASE_URL` | нет | SQLite в `db.sqlite3` | Адрес базы данных, например `postgres://user:password@localhost:5432/star_burger`. |

## Как получить ключ Яндекс.Геокодера

Расстояние от ресторана до клиента сайт считает по координатам, а координаты по адресу узнаёт у Яндекса. Для этого нужен ключ API:

1. Войдите в [Кабинет разработчика Яндекса](https://developer.tech.yandex.ru/services/) под своим аккаунтом.
2. Нажмите «Подключить API» и выберите тариф с HTTP Геокодером — у Яндекса есть бесплатный.
3. Заполните форму подключения. Ключ обычно выдают сразу, он появится в списке ваших сервисов.
4. Скопируйте ключ и положите его в `.env`:

   ```sh
   YANDEX_GEOCODER_API_KEY=ваш-ключ
   ```

Проверить, что ключ работает, можно не открывая браузер:

```sh
python manage.py shell -c "from geocoder.coordinates import fetch_coordinates; print(fetch_coordinates('Москва, Тверская улица, 1'))"
```

Среди вывода команды должна появиться строка с координатами: `Coordinates(lat=55.756315, lon=37.614716)`. Если вместо неё напечатано `None` — ключ не принят, либо кончился суточный лимит запросов, либо нет интернета.

У бесплатного тарифа есть суточный лимит запросов, поэтому проект запоминает ответы геокодера в базе: один адрес стоит одного запроса за всё время жизни проекта, дальше координаты берутся из таблицы «геокэш адресов». Её видно в админке, и оттуда же можно удалить адрес, чтобы спросить его заново.

## Как запустить тесты

```sh
python manage.py test
```

Тесты проверяют оформление заказа через API, снимок цены в позициях заказа, подбор ресторанов и сортировку по расстоянию, расчёт расстояний, кэш геокодера, страницы кабинета менеджера и то, что список заказов не начинает ходить в базу за каждым заказом отдельно. Интернет им не нужен: геокодер в тестах подменяется.

## Как запустить prod-версию сайта

Собрать фронтенд:

```sh
npm run build
```

Настроить бэкенд — в файле `.env` рядом с `manage.py`:

```sh
DEBUG=False
SECRET_KEY=ваш-секретный-ключ
ALLOWED_HOSTS=example.com,www.example.com
YANDEX_GEOCODER_API_KEY=ваш-ключ
```

Собрать статику в каталог `staticfiles`, откуда её будет раздавать nginx:

```sh
python manage.py collectstatic --no-input
```

Отмигрировать базу:

```sh
python manage.py migrate
```

И запустить сайт любым WSGI-сервером. Например, gunicorn — его нужно поставить отдельно, в `requirements.txt` его нет, потому что для dev-режима он не нужен:

```sh
pip install gunicorn
gunicorn -b 127.0.0.1:8000 star_burger.wsgi:application
```

## Структура проекта

Код разложен по трём приложениям:

- `foodcartapp` — меню, рестораны и заказы: модели, API для сайта и подбор ресторанов под заказ (`logistics.py`).
- `restaurateur` — кабинет менеджера: страницы со списком заказов, карточкой заказа и его редактированием.
- `geocoder` — координаты адресов: запросы к геокодеру Яндекса, кэш ответов в базе (`Geocache`) и расчёт расстояний.

Зависимости идут в одну сторону: `restaurateur` и `foodcartapp` знают про `geocoder`, а он про них — нет.
